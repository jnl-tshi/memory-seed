# Proposed Reflection runtime retirement plan

This is a plan, **not approval or execution**. The request is to stop investing in the Reflection Board/workstream-ledger machinery while retaining ordinary Memory Seed behavior. Reflection is currently `dormant`, but ordinary commits, session integration, packet compilation, ESR, CLI, and MCP still enter its code. The dedicated runtime is about 4,972 lines in `memory_seed/reflection_ledger.py` and `memory_seed/reflection_operations.py`, plus a 51-line profiler. The seven dedicated test modules were already removed; that did not remove production behavior. Baseline: clean `main` at `1c033a3fc9111dc532b3c52e3d56acac7b80020c` when this plan was drafted. Rebind every task to its measured execution base rather than treating this SHA as permanently current.

## Scope and authority gates

- **G0 — maintainer decision, coordinator-owned.** JNL explicitly approves or declines runtime retirement, chooses how the tracked `.memory-seed/reflections/active/rwl_0xf1x07gms0zk0q1fa31/ledger.md` and `.memory-seed/reflections/trust/retention-approval.yaml` remain accessible, then considers an explicit proposal to retire Constitution Invariant #2's temporary-board clause under §11. No behavior task begins until the amendment is ratified; this planning request itself authorizes neither the amendment nor code removal. Recommended disposition: preserve exact tracked bytes as read-only historical material in place, with plain-file/Git access; do not simulate expiry, forge receipts, remove a key, or relocate/delete the board without a separately approved migration. Preserve ordinary sessions, decisions, ADRs, and policy history append-only. Record supersession of the prior *temporary pause* rationale, including why inspection/admission was retained then.
- **G1 — execution readiness, coordinator-owned.** Confirm current code and accepted authority heads; snapshot clean base, installed hook type/content, active worktrees, exact tracked board paths, and current baseline failures. Verify official Superpowers skills are exposed by the active client **and** observe release `>=6.2.0,<7.0.0`; skill exposure is visible now, release is unverified. If release cannot be verified, name the fallback: Memory Seed sequential bounded workers with its own review gate, not an invented version or automatic install. Check `.superpowers/sdd/` is ignored before any SDD scratch. No graph regeneration.
- **G2 — safe landing.** The old installed `prepare-commit-msg` hook calls `reflection_operations` before `Memory-Entry` stamping, and the old `session merge-branch` path imports Reflection during preview/apply. Land a first, green compatibility tranche that removes Reflection callers from ordinary paths **while keeping the two runtime modules and tracked board intact**. Integrate it through the existing guarded session merge; never bypass hooks or use raw merge to evade a refusal. Upgrade/verify the installed hook through the supported installation path, preserving unrelated hook customizations and trailer stamping. Only after the integration tree itself no longer needs the modules may a second tranche delete them. If the old/new parser or hook cannot safely land either tranche, stop and design an approved migration bridge; do not force a merge.

## Global constraints and worker contract

Memory Seed owns branch/worktree creation, namespace guard, permissions, Task Packets, durable session entries, integration, and cleanup. Superpowers is an optional disposable same-session execution/review layer, not a new authority or worktree controller. Do not invoke its `using-git-worktrees` or `finishing-a-development-branch`. SDD never runs two writing implementers in the same worktree concurrently; tasks below are serial wherever they share imports, behavior, or files. Independent read-only scouts may overlap (at most three workers with the coordinator occupying the fourth slot); no beneficial parallel implementation is currently identified. If genuine isolated code-writing lanes later appear, use Memory Seed Fan-Out with separate worktrees and sequential integration, not SDD parallel writes.

Each future worker gets a fresh, packet-only context of roughly 100–250 words of project purpose plus the exact task brief, not this conversation. Its packet names a verified `base_sha`, owned worktree/branch, preflight (`python -X utf8 -m memory_seed.cli worktree guard --agent codex --write-intent`, `pwd`, Git top level/HEAD/status), exact allowed files and inclusive line ranges at that base, forbidden files, dependencies, baseline result, acceptance tests, and output/report path. New paths require an absence check. It may read but not edit forbidden evidence. The coordinator resolves an actual model and effort explicitly at dispatch; tiers below are durable requirements, **not** a claim about which model ran. `economy` means exact mechanical 1–2-file tasks, `balanced` is the floor for prose-based integration or meaningful review, and `frontier` owns architecture, authority, and whole-branch review. Initial context allowances: economy ≤8k, balanced ≤16k, frontier ≤30k task-specific input tokens, with separately stated output reserve and an explicit stop before overrun. These are estimates, not observed usage or prices.

Each SDD task writes tests before its behavior change where applicable, reports its exact commit range and focused validation, then receives an independent spec-and-quality review. Fixes use Superpowers' five-round maximum (same worker rounds 1–3; fresh stronger worker rounds 4–5); unresolved load-bearing findings stop. One frontier whole-branch review follows each tranche, with at most one consolidated final fix wave and one scoped re-review. Do not stack Memory Seed Fan-Out's separate review controller on top of SDD. Do not run the full suite after every tiny task; run task-targeted checks, then whole-branch and integrated-tree checks. `progress.md` and reports under ignored `.superpowers/sdd/<plan>/` are scratch; only validated handoff receipts enter Memory Seed history.

## Acceptance, exclusions and stop rules

Done means ordinary operations no longer scan/admit Reflection state; no supported CLI/MCP command, packet field, config, or new seed prompt activates it; the tracked ledger/trust and historical sessions/ADRs remain readable; OSS Markdown authority, hosted SQL authority, ordinary write validation, `Memory-Entry` trailers, append-only fuse, sidecar checks, and worktree guards remain intact. Search for **active** references rather than demanding zero historical occurrences. Hosted branch identity/status, authenticated user-versus-agent intent, governance approval, curated memory, logging, provenance and retrieval stay independent. This plan does not build a hosted service, rewrite unrelated memory infrastructure, remove Superpowers, fix unrelated baseline failures, publish, push, or delete user artifacts.

Stop for absent constitutional approval, uncertain board/key disposition, an installed hook that cannot be upgraded without overwriting user customization, old-guard/new-code integration deadlock, an unexpected reserved-path edit, a real new generic safety regression, an authority conflict, a load-bearing review finding at the circuit breaker, or a stale task base/scope. Preserve the branch and report exact evidence rather than bypassing guards. Historical full-suite failures previously included unrelated categories; the current baseline must be freshly measured, not assumed to be 21 or automatically blamed on Reflection.

Estimated effort: several focused engineering days to roughly two weeks, depending mainly on the guarded landing path, installed hooks and full-suite triage. The worker/reviewer count is approximately 8 SDD tasks × 2 roles plus one or two frontier whole-branch reviews, excluding bounded fix rounds; this is a planning estimate, not a cost or usage claim. Review the plan again after G0, then approve execution separately.
