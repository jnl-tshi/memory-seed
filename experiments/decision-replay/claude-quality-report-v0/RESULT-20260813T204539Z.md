## Adjudication: the v1 grader over-specified implementation shape

The task required that an unreadable input "must not be converted into a successful coverage number."
The preregistration used the same behavioral boundary. It did not require exception propagation.

Both subjects independently chose a second honest behavior: return `draft_reason_coverage` with status
`unavailable` and no numerator, denominator, or rate. Arm A retained the already-known population; Arm B
reported a zero population. Neither returned a successful coverage number. The v1 hidden test therefore
rejected two implementations that met the disclosed contract and contradicted the instrument's claim
that it graded behavior rather than patch shape.

Grader schema v2 now accepts either of two honest outcomes under the injected read failure:

1. fail fast by propagating `OSError`; or
2. return explicit `unavailable` with no coverage number.

It still rejects the pristine source, which swallows the error and reports measured coverage, and the
withheld historical fix still passes. Regrading the untouched candidates under v2 makes both arms pass
all four gates. The original v1 JSON outputs are preserved and are not rewritten.

## Treatment-uptake audit

The historical-rationale arm did receive a different SessionStart payload, but the relevant rationale
was not delivered into active reasoning:

- B's generated startup output was 9.8 KB and overflowed into a persisted Claude tool-result file. The
  model transcript contained only a roughly 2 KB preview plus the path to the full output.
- B did not open that persisted output, open a dated session document, or call `memory_search`.
- The preview exposed general recent project context, not the quality-report defect. The only pre-fix
  entry that flagged the defect was the truncated `2026-08-03 20:14` entry's follow-up, beyond the
  visible preview.
- A had no dated session documents and received a 1,797-character startup context. B's transcript held
  a 2,188-character persisted-output wrapper/preview plus the same 593-character retrieval reminder.

Accordingly, this pair supports an **availability-level** observation under normal routing, not a
content-exposure comparison. The treatment existed on disk, but uptake of the relevant rationale was
zero. The 58% timing difference is real and worth replicating, but it cannot be attributed to the
bug-specific historical rationale from this run.

The transcript also provides a simpler non-memory explanation for much of the time difference. A ran 23
Bash calls, five edits, four reads, broad suite checks, and mutation-style regression checks. B ran 15
Bash calls, four edits, four reads, and a narrower validation set. Both converged on nearly the same root
diagnosis and structured-`unavailable` design.

## What this pilot establishes

- The historical fixture, blinding, scope gates, public tests, and nested-runtime negative control work.
- A single available-memory arm can finish materially faster even with additional startup context; the
  observation is a replication target, not a causal finding.
- Availability is not exposure. A study of rationale quality needs an explicit manipulation check that
  records which entry or decision reached the model before implementation.
- A hidden behavioral grader must accept all behaviors permitted by the task, not only the historical
  patch's failure mode.

## Required changes before a scored study

1. Freeze grader schema v2 and rerun `verify_harness.py` before preparing a new pair.
2. Record treatment uptake automatically: injected entry IDs, persisted-output reads, retrieval calls,
   and whether the task-relevant decision entered model context.
3. Prevent startup overflow from silently hiding the treatment. Use a bounded task-relevant packet or a
   three-arm design: current state, historical memory merely available, and the relevant rationale
   explicitly pushed.
4. Run multiple independently fresh sessions per arm with randomized order. Report correctness, elapsed
   time, unique API messages, tool calls, token categories, and validation breadth per run.
5. Keep time as a secondary outcome unless every arm uses a fixed test/validation budget; otherwise
   "faster" can mean less checking rather than faster reasoning.

## Withdrawn conclusions

This pilot withdraws two tempting conclusions:

- **Withdrawn:** both implementations were unsafe because the original hidden gate failed. They withheld
  the coverage number honestly; the gate was narrower than the task.
- **Withdrawn:** B's faster result demonstrates that preserved rationale caused a better later decision.
  B was faster, but the task-relevant rationale never entered its active context.

The retained conclusion is deliberately narrower: B was 2.36 times faster in this one availability-level
pair, both candidates satisfied the corrected behavioral contract, and the next experiment must make
treatment exposure observable.
