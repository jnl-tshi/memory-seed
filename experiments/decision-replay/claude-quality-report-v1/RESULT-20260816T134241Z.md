## Human review of the candidates

### A — good implementation, incomplete handoff

A retained known population/exclusion information when an affected source was unreadable and added
three well-discriminated regression tests. Its code passed the frozen behavioral grader. The handoff was
not complete: it ended on a waiting message, omitted the receipt and memory-use declaration, and did not
adjudicate its background full-suite result.

### B — strongest self-contained verification, without claimed memory use

B produced the broadest regression surface: root/nested report equivalence, nested-runtime ownership,
unavailable rendering, and a read-only/determinism check. Its unavailable result retained the known
population and exclusion counts, capped displayed unreadable paths, and documented the behavior clearly.
It also separated the broken format re-read from the already-correct chunk-based metric. This was the
strongest overall implementation/handoff in the pilot, but B explicitly attributed none of it to memory.

### C — observable rationale use and strong residual-risk disclosure

C clearly connected the supplied entry to the correct join-base diagnosis and disclosed useful residual
risks, including the status change, precedence choice, uncaught decode failures, and an adjacent join it
did not modify. Its patch and regression tests passed. Compared with A and B, its `unavailable` metric
discards otherwise known population/exclusion counts by setting both to zero, which is safe but less
informative. The pushed rationale demonstrably influenced the search narrative, but did not improve the
binary outcome or total time.

## What this pilot establishes

- The corrected grader accepts both honest unreadable-input behaviors and rejects the pristine defect.
- A bounded rationale packet can be delivered and its use can be confirmed in a fresh session.
- Preserving history and exposing an entry ID are not sufficient evidence that the decisive part of the
  rationale reached or influenced the model.
- The same correct behavior can be reached without dated memory on this relatively direct defect.
- Binary pass/fail alone is too coarse for this case; the observable differences were in verification,
  handoff completeness, retained information, and residual-risk disclosure.

## What this pilot does not establish

- It does not establish a general Memory Seed quality, speed, or token-efficiency effect.
- It does not establish that pushed rationale was necessary for this fix.
- It does not establish that normal routing delivered the bug-specific rationale.
- It does not establish that A was more efficient; A stopped before completing the reporting contract.
- It does not rank the three conditions statistically: there was one subject per arm and execution order
  was not replicated.

## Instrument changes before a scored study

1. Use a harder historical decision where current code and task wording permit at least two plausible
   implementations, and the preserved rationale predicts a safer choice that a behavioral oracle can
   distinguish. This case was too directly diagnosable from the source.
2. Replace entry-ID exposure with **content-level exposure**: pre-register a non-leading hash, phrase, or
   proposition from the decisive rationale and confirm that exact content reached model-facing context.
3. Make receipt and memory-evidence fields machine-enforced completion gates, or record a separate
   protocol-compliance outcome. A should not look faster because its final handoff ended early.
4. Add a blinded human-quality rubric for test discriminativeness, unsupported claims, retained
   information, residual-risk disclosure, and review effort. Preserve binary correctness as the primary
   safety gate rather than replacing it.
5. Measure later decision replay directly: give a new maintainer the resulting patch plus its evidence,
   then score reconstruction accuracy, safe override quality, and review time after a delay.
6. Run multiple independently randomized subjects per arm before estimating an effect. Stratify or cap
   validation only if elapsed time is promoted beyond a descriptive outcome.

## Withdrawn conclusions

This run withdraws four tempting conclusions:

- **Withdrawn:** the earlier B-over-A speed difference is likely to reproduce as a rationale benefit.
  Here the rationale-uptake arm was slowest, and validation breadth dominated total time.
- **Withdrawn:** an exposed relevant entry ID proves the relevant rationale was exposed. B saw the ID
  but the startup payload truncated the entry before the defect-specific follow-up.
- **Withdrawn:** the pushed rationale produced a better implementation outcome on this case. All three
  arms passed; B's no-claimed-memory handoff was arguably the strongest overall.
- **Withdrawn:** A's 6m52s completion is an efficiency result. A omitted required final fields and ended
  before reviewing the background suite, so the timing is protocol-incomplete.

The retained conclusion is narrower: explicit rationale delivery and claimed use are now observable,
but this task exhibits a correctness ceiling and provides no evidence that memory improved the later
decision. The next study needs content-level exposure checks and a decision where rationale can change a
measurable choice.
