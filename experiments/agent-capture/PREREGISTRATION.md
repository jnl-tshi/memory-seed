# Pre-registration — agent decision-capture experiment

**Committed before any scored run. Changes after the first scored run require a dated amendment
block; silent edits invalidate the result.**

## Question

Do agents with the Memory Seed MCP write path available record their durable decisions **without
per-session human prompting** — and what is the minimum scaffolding level at which capture becomes
reliable?

This is the first validation question in `business/wedges/developer-project-memory.md` (the ratified
agents-first operating premise), and the untested defence of write-time capture identified in field
evidence E2: enforcement is only "cheaper than not capturing" if the agent actually does it.

## Design

Scaffolding dose-response across four fixture levels, each a complete standalone Memory Seed
install generated by `generate_fixtures.py` from real `init_project()` output plus documented strips:

| Level | Scaffolding |
|---|---|
| L0 | MCP write path only (store + topics.yaml + `.mcp.json`). No routing files, no rules, no hooks |
| L1 | L0 + one `AGENTS.md` line naming the store |
| L2 | Full install (routing, agent-rules contract, skills registry), hooks removed |
| L3 | Full stock install: rules + agent hooks + git commit hook |

Unit: one headless session (`claude -p`, cwd = run directory) given one task brief. Tasks are
frozen (`tasks/tasks.json`); briefs never mention memory, recording, or documentation. Assignment
of tasks to arms is exhaustive (every task runs at every level), repeated N times per cell.

**Constants across all arms** (difference out): the harness permission flag
(`--dangerously-skip-permissions`), the user-level `~/.claude/CLAUDE.md`, the model and version
(recorded per run in `RUN_MANIFEST.json`), the stub project, the briefs.

## Metrics

| Metric | Definition |
|---|---|
| **Capture rate** | judged seeded decisions recorded ÷ seeded decisions present (per answer key) |
| **Latency** | recorded in the same turn as the decision / at session end / never |
| **Faithfulness** | blind judge: does the recorded `R:` match the transcript's actual reasoning? |
| **Noise rate** | recorded entries with no seeded referent ÷ recorded entries |
| **No-diff capture** | capture rate on T3-D1 specifically (the decision that produces no code diff) |

## Judging

Blind packets built by `collect.py`: task brief + transcript + recorded entries. **Packets never
contain the answer key or the level label.** Judge is a different model family from the subject
where available (cross-model), with a human adjudication sample of ≥15 disputed or borderline
cases. Dropped/unscorable units stay in the denominator (topic-swarm harness rule).

## Thresholds (stated in advance)

- A level is **"reliable capture"** if judged capture rate ≥ 0.8 on required seeded decisions with
  noise rate ≤ 0.3 across all tasks in that arm.
- The mechanical-cheapness claim (premise's strongest form) **survives** if L1 or L2 reaches
  reliable capture. It **fails** if only L3 does — the honest claim then becomes "the shipped
  control plane makes agents record", and E2's enforcement-is-not-cheapness criticism stands.
- **Kill condition:** if L3 — hooks, escalation, full contract — misses seeded decisions at a
  judged capture rate < 0.5, the write-time story is wrong regardless of scaffolding, and the
  passive-capture architecture must be treated as the stronger alternative.

## Arm sizes

Smoke probes (1 session each, L0 and L3) validate the instrument and are **not scored**. Scored
arm sizes are set after the smoke probes against the approved token budget; the planned shape is
N ≥ 5 sessions per (level × task) cell, i.e. ≥ 60 scored sessions for the 4×3 matrix.

## Known limitations, stated now

1. **Experimenter = subject population.** A Claude agent designed the tasks and will run Claude
   agents. Mitigations: this pre-registration, blind packets, cross-model judging, human
   adjudication, transcripts preserved, null published. Compensation, not cure — external
   replication on a foreign corpus remains the only cure (Report 4, Phase 2).
2. **The tool's description is itself a weak prompt.** True zero-scaffolding is unreachable; L0
   measures "tool visible, nothing else", not "no signal at all".
3. **Single stub project, three tasks.** Task heterogeneity is controlled by freezing, not by
   sampling breadth. Results generalise to these task classes, not to all engineering work.
4. **Headless ≠ interactive.** No human interrupts, no mid-session steering. This matches the
   delegated-agent use case the premise targets, and does not match pair-style usage.
