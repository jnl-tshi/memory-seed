# Prospective Codex rollout exposure baseline

Status: offline research instrument, 2026-10-02. This baseline is **not** a fresh decision corpus or an accuracy result.

`freeze_exposure.py` reads local Codex rollout metadata using the existing `align_decisions.py` reader. It groups physical rollout files by logical session, follows parent-thread links to a canonical root, hashes every source file, and writes a private metadata manifest outside Git. It does not copy conversation text. Missing, conflicting, cyclic, unparsed, or changing source metadata is not eligible for a fresh-root claim. The command refuses to overwrite a snapshot or write one inside a Git checkout.

The first timestamped private baseline contained 1,707 rollout files and 631 resolved roots (1,072 files named a parent; four files were continuations of an existing logical session). The source-row digest was `711e610ec47113f6f106bb4d645225394bf4f94fefc825e53a960d1e93570693`. All roots present in it are conservatively **prior-or-unknown exposure**, even if they were not actually shown to a model. A subsequent root counts as prospectively new only when its lineage resolves uniquely, its root ID is absent from this baseline, and its recorded start is after the freeze timestamp. This still does not prove the root was never exposed by another system; a model/reviewer exposure ledger is required before a gate claim.

An immediate second snapshot found **zero** new independent roots. The comparison refuses a freshness claim if either snapshot contains unresolved rollout metadata. Existing files may change as active sessions continue, so their source hashes can change without creating a new root.

Two private historical negative-candidate pilots calibrated the prefilter without assigning gold labels. The first five lexical candidates were one-turn evaluation/classification exchanges, not ordinary decision discussions. The next two were multi-turn dialogue projections with omitted tool events disclosed by count. Independent reviewers agreed on **zero** real hard negatives across these pilots; one case was a routine capability question and one had conflicting acceptance/sufficiency judgments. The pilots are diagnostic only and must not enter the fresh 30/30 gate.

To reproduce a new private snapshot, choose a new output file in a private directory outside any Git checkout and run `python -X utf8 experiments/decision-chat-alignment/freeze_exposure.py --private-output <path>`. Later, add `--baseline <earlier-private-snapshot>` to count new independent roots; the identity list stays in the private output, while stdout reports counts only. Preserve the output and tool/source digests privately. Do not commit raw rollouts, source paths, root IDs, or review windows. A fresh trial additionally needs independent source-reviewed positives and real hard negatives from disjoint new roots, two independent model runs, two masked semantic reviews, and an agreed model/spending bound.
