### Summary

- Made `_chunk_from_storage` tolerant of a cache written by an older binary, so a stale projection degrades to a rebuild instead of 500-ing the whole Trail.

### Decision

- D: The cached-chunk loader no longer trusts the stored shape blindly. A renamed field is canonicalised (`supersedes` → `replaces`, merged without duplicates) so its edges survive; any other unknown key is dropped rather than passed to `MemoryChunk(**data)`. A stale cache therefore degrades to a rebuild, never a hard crash.
- R: A pre-rename cache carrying `supersedes` raised `unexpected keyword argument` and took the entire Trail down (500 on every request) until the cache file was found and cleared by hand — observed live 2026-07-24 when an old orphaned server's cache was read by the new binary. The cache is a rebuildable projection (Constitution: every DB/cache is derived), so a crash on READ is strictly worse than a stale read: the stale read loses at most one field until the next rebuild, the crash loses the UI. Canonicalising the renamed field also honours the vocabulary rename's standing promise to read the old spelling forever, which the cache reader was silently violating.
- A: Bump a cache schema version so a shape change invalidates the cache proactively — the more thorough fix, but bigger, and it does not help a cache already on disk from a mismatched binary; deferred. Just deleting the cache on mismatch — rejected as more destructive than needed when the data is readable after canonicalisation.
- F: `memory-trace/memory_trace/service.py` (`_chunk_from_storage`, `fields` import).
- T: `memory-trace/tests/test_incremental_projection.py::ChunkStorageSchemaDriftTests` — reverting the fix reproduces the exact live `TypeError: unexpected keyword argument 'supersedes'`; with it, the renamed field canonicalises, merges without duplicates, and an unknown key is dropped. 207 memory-trace tests pass.

#### D2 - Defer decision-level topic keying to a proposal, and reject a third axis

- D: Keying each topic to its decision (`topic:dN`) is written up as a proposal and deferred, not built. A third mandatory topic axis is rejected. The proposal doc also records the live topic-inference conventions (two-axis model, cross-cutting concerns as rare add-ons, the cap) — the durable home for what the backfill swarm prompt teaches.
- R: `topic:dN` would mirror the `:dN` lifecycle grammar and unify the multi-decision question elegantly, but topics are a fuzzy associative signal where per-decision precision fights their purpose (a lifecycle edge is a precise claim; a topic is soft aboutness). ### Summary

- Extended topic sidecars to decision granularity before any backfill runs, and stated the

### Decisions

#### D1 - Build the decision-level topic grammar before the backfill, not after it

- D: Topic sidecars gain `<slug>:dN` alongside bare slugs, with the ordinal validated against the
  entry's real decisions (`dangling-topic-decision`), a malformed-suffix error
  (`malformed-topic-ref`), a per-decision cap of 3 (`MAX_TOPICS_PER_DECISION`) with the rolled-up
  entry union left uncapped, and the redundancy rule inverted so a decision-keyed slug naming a
  topic the author wrote at entry level reads as enrichment rather than restatement. Bare slugs stay
  legal permanently.
- R: JNL directed building decision-level from the start and scanning the full corpus. Measurement
  settles the sequencing: the backfill is **881 decisions across all 621 entries** either way,
  because the 415 already-topiced entries carry no per-decision attribution, so an entry-level pass
  first would add 206 judgments the decision pass then re-derives. Bare slugs cannot be a migration
  stage because **33 entries record no decision at all** — a note is still about something. Roll-up
  to entry level is required and deliberately inverts the link precedent: `check_topics` and every
  other consumer read entry-level topics, so without it a fully decision-tagged entry still reports
  as topicless. Rolling `graph:d1` up to "partly about graph" invents no claim, whereas rolling
  `A:d1 -> B:d2` up to `A -> B` would.
- A: Entry-level backfill now, decision-level later — rejected: same 881 judgments, plus a second
  written pass. A third mandatory topic axis — previously assessed and rejected; unchanged.
- F: `memory_seed/core.py`, `tests/test_links_check.py` (six tests),
  `docs/3_Spec/draft/decision-level-topic-sidecars.md`, `docs/2_Todo/decision-level-topics-proposal.md`.
- T: 726 backend tests pass; live corpus reports `Session memory integrity OK` (90 files).

#### D2 - One append-only supersession rule for all three sidecar families, with the unit differing

- D: An extraction sidecar is append-only and, for any named reference, the newest declaration wins
  on a (file date, block timestamp, position) sort. Topics and diagrams supersede per **entry**;
  links supersede per **edge**. Topic block identity becomes `(entry_id, heading timestamp)`, so a
  later block is a legal re-attribution and only a same-timestamp collision in one file errors.
  Diagram sidecars adopt the same identity, supplying the append path they currently lack.
- R: JNL set most-recent-wins as the general approach for extraction sidecars. It generalises, but
  the unit is load-bearing: links are set-shaped under four never-merged edge kinds, so block-level
  replacement would erase edges nobody named. Links therefore keep `retracts:` — removal is
  otherwise inexpressible (no kind means "none") and reclassification is ambiguous against adding a
  parallel edge of another kind. That makes `retracts:` the explicit form of the same rule rather
  than an exception. Diagram block identity is `entry_id` alone today, which is precisely why
  Constitution v1.4 needed a human-gated in-place Mermaid repair exception; the append path makes
  that exception non-load-bearing.
- A: Apply block-level last-wins uniformly including links — rejected: silently drops edges.
  Replace `retracts:` with implicit last-wins — rejected: cannot express removal, and guesses on
  reclassification.
- F: `docs/3_Spec/draft/sidecar-supersession-model.md` (new).
