### Summary

- Root-caused entries rendering as orphans despite having authored relationships, fixed the dominant
  cause, and reworked how the Graph's Show more selects entries.

### Decisions

#### D1 - Give graph edges their own payload ceiling, separate from nodes

- D: `EDGE_PAYLOAD_CEILING = 6000` governs edges; nodes keep the 1000 ceiling.
- R: The cap was `max(limit, len(nodes))`, so edges were bounded by the node count. Measured on the
  real corpus: 626 entries carry **1231** entry-level lifecycle edges, so 231 were silently cut, and
  **133 of the 215 apparent orphans were pure truncation** — nodes drawn with the relationships that
  justify their presence removed. Node count is what `limit` governs; once a node is in, the edges
  among the selected set are the whole point of drawing it. The intra-slice set is self-bounding by
  node count, so a higher ceiling is not open-ended. Orphans fell 215 → 82.
- A: Raise the shared ceiling — rejected: node and edge counts scale differently, and a slice of N
  nodes holds many times N edges. Leave it and accept sparse maps — rejected: the map was wrong.
- F: `memory-trace/memory_trace/service.py`.

#### D2 - Overview selection is a chronological spine plus one hop, not a connectivity ranking

- D: `_overview_slice` takes the newest `limit` entries as a spine, then expands one hop over the
  lifecycle edges currently rendered, pulling in referenced entries regardless of date. `limit` sizes
  the spine; expansion is additive.
- R: JNL: the Trail must stay purely chronological, and the Graph should lead with the same
  chronological core so the spine is shared, with the Graph adding relationship context for
  visualisation. The old greedy connectivity ranking (highest-degree seeds, frontier by degree) built
  a well-connected map whose membership had no relation to what the user was reading. That ranking
  existed to avoid an edgeless slice, since plain corpus order starts at the OLDEST entries;
  newest-first avoids that by construction, because recent entries are the linked ones. Measured: the
  window recedes monotonically (06-15 → 06-12 → 06-03 → 05-26) as Show more is pressed.
- A: Expand iteratively rather than one hop — rejected: one old entry would drag its whole
  neighbourhood in. Change the Trail too — rejected by JNL; the Trail stays chronological.
- F: `memory-trace/memory_trace/service.py`, `memory-trace/tests/test_service.py`.

#### D3 - Decision-level edges stay out of the entry-level surface; the fix is decision rows

- D: Reverted an attempt to emit entry-level lines for decision-level edges. Recorded the remaining
  9 orphans and the sanctioned fix as a NEXT_STEPS item instead.
- R: `test_decision_edges_never_reach_entry_level_consumers` asserts by set-equality against a
  sidecar-deleted control that the entry-level surface is indistinguishable from a world where
  decision edges were never built. That guard is deliberate and reasoned, so lifting it is a contract
  decision rather than an implementation one — "don't remove guards you don't understand". The real
  fix costs nothing structurally: `_expand_decision_rows` exists and `include_decisions` is Trail-only,
  so having the Graph render decision rows gives these edges a genuine endpoint. It is also step 1 of
  the decision-node-graph sequencing already recorded.
- A: Mark the emitted edges `decision_derived` and keep them — rejected: the guard tests the edge SET,
  not its labelling, and a marker does not make the surface indistinguishable.
- F: `memory-trace/memory_trace/service.py` (comment recording the attempt), `docs/2_Todo/0_NEXT_STEPS.md`.

#### D4 - The inspector separates edge direction, and `Links` counts rendered lines

- D: Replaces / Evolves / Related each get their own row with per-item direction (outgoing marked with
  an arrow and accent border, incoming dashed). `Links` now counts edges rendered for that node under
  the current edge-type filter.
- R: Three independent never-merged edge kinds deserve three rows — "retires", "refines" and "also
  see" are different claims. Direction rides on the item rather than splitting into six rows, since
  incoming and outgoing are one relationship seen from two ends. Surfacing inbound edges at all is
  new: the previous row was outbound-only, so one sample entry's five inbound `evolves` were
  invisible. `Links` previously showed `connectivity`, a **related-only** display weight that drives
  node radius — left untouched server-side so the graph's visual encoding does not silently change.
- A: Redefine `connectivity` server-side — rejected: it would change node sizing, which nobody asked
  for. Six rows split by direction — rejected: buries that they are one tie.
- F: `memory-trace/client/src/App.tsx`, `memory-trace/client/src/styles.css`.
- T: 212 memory-trace tests pass. Verified live: `Links: 5` equals the node's rendered cytoscape
  degree, direction marks render correctly, and the previously-orphaned screenshot entry now has
  degree 6.
