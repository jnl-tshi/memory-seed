### Decisions

#### D1 - Give graph edges their own payload ceiling, separate from nodes

- D: `EDGE_PAYLOAD_CEILING = 6000` governs edges; nodes keep the 1000 ceiling.
- R: The cap was `max(limit, len(nodes))`, so edges were bounded by the node count. Measured on the
  real corpus: 626 entries carry **1231** entry-level lifecycle edges, so 231 were silently cut, and
  **133 of the 215 apparent orphans were pure truncation** — nodes drawn with the relationships that
  justify their presence removed. Node count is what `limit` governs; once a node is in, the edges
  among the selected set are the whole point of drawing it. The intra-slice set is self-bounding by
  node count, so a higher ceiling is not open-ended. Orphans fell 215 → 82.
- A: Raise the shared ceiling — rejected: node and edge counts scale differently, and a slice of N
  nodes holds many times N edges. Leave it and accept sparse maps — rejected: the map was wrong.
- F: `memory-trace/memory_trace/service.py`.

#### D2 - Overview selection is a chronological spine plus one hop, not a connectivity ranking

- D: `_overview_slice` takes the newest `limit` entries as a spine, then expands one hop over the
  lifecycle edges currently rendered, pulling in referenced entries regardless of date. `limit` sizes
  the spine; expansion is additive.
- R: JNL: the Trail must stay purely chronological, and the Graph should lead with the same
  chronological core so the spine is shared, with the Graph adding relationship context for
  visualisation. The old greedy connectivity ranking (highest-degree seeds, frontier by degree) built
  a well-connected map whose membership had no relation to what the user was reading. That ranking
  existed to avoid an edgeless slice, since plain corpus order starts at the OLDEST entries;
  newest-first avoids that by construction, because recent entries are the linked ones. Measured: the

- A: Expand iteratively rather than one hop — rejected: one old entry would drag its whole

### Decisions

#### D1 - Decision rows in the Graph are an opt-in change of granularity, not an entry-level edge

- D: `/api/v1/graph/projection` accepts `include_decisions` (default **false**), and `graph()` gains
  `decision_row_scope`. The entry-level surface is byte-identical when the flag is off.
- R: This is NEXT_STEPS item 8 — the fix for entries whose only relationships are decision-level and
  therefore render as orphans, because an entry-per-node view has no row for `B:d2 evolves A:d1` to
  land on. Emitting an entry-level line instead was tried on 2026-07-26 and reverted against
  `test_decision_edges_never_reach_entry_level_consumers`. Asking for rows is legitimate where
  forging an edge is not: the edge terminates on the decision it actually names, and the claim
  grammar v2 forbids ("B evolves A" as an authored entry-level edge) is still never made.
- A: Make it the default — rejected: it changes every existing consumer's granularity for a 9-entry
  tail. Keep forging entry-level edges behind a marker — rejected: the guard tests the edge SET, so a
  label does not make the surface indistinguishable.
- F: `memory-trace/memory_trace/service.py`, `memory-trace/tests/contract/openapi.v1.json`,
  `memory-trace/tests/contract/types.ts`.

#### D2 - Expansion is filtered by ORDINAL, and the Trail and Graph want different scopes

- D: `decision_row_scope="all"` (Trail) expands every decision of every multi-decision entry;
  `"linked"` (Graph) expands only the ordinals a decision edge terminates on. `_expand_decision_rows`
  takes `only_ordinals` rather than a set of entry ids.
- R: Measured, not stylistic. A timeline row earns its place by existing, so the Trail's rule (and its
  "a document does not skip heading 1" reading) is right there. A force layout is the opposite: a row
  with no edge is simply a new isolate. Expanding the whole corpus produced **446 rows of which 276
  were isolated** — a cure worse than the 9 orphans it set out to fix. Filtering by entry got that to
  110; filtering by **ordinal** gets it to **0**, because a row then exists exactly where a
  relationship lands. A graph is not a document, so the heading rule does not carry over. The group
  anchor keeps the entry id, so entry-level edges still terminate correctly.
- A: Filter by entry — rejected, measured at 110 isolates. Emit rows for all ordinals and hide
  edgeless ones client-side — rejected: the server should not ship nodes it expects the client to
  discard.
- F: `memory-trace/memory_trace/service.py`, `memory-trace/tests/test_trail_decision_edges.py`.
- T: 213 memory-trace tests pass. New test asserts the default stays entry-per-node, that opting in
  produces rows, that **no row is edgeless**, and that opting in never removes an entry node.

### Follow-up

- **Anchors can now float.** Full-corpus orphans go 83 → 94 with rows on: ~11 anchors whose only
  edges were decision-level are now edgeless while their rows carry the relationships. A timeline

### Summary

- Shipped the user-facing confidence threshold deferred when `edge_confidence` landed: the graph
  faded low-confidence edges but offered no way to hide them.

### Decision

- D: A three-step control in the graph filter bar — **All / ≥0.7 / ≥0.9** — hiding machine-suggested
  edges below the chosen score. Defaults to All and persists with the other graph settings.
  Human-authored edges are never hidden by it. A filtered edge is also removed from the per-pair
  outranking input, not merely hidden.
- R: The thresholds reuse the tiers the sidecar already stores (`low` <0.7, `review` ≥0.7, `high`
  ≥0.9), so the control filters on exactly the boundaries the graph already fades on rather than
  inventing a second, disagreeing notion of "confident". Defaulting to All follows the same reasoning
  as the Orphans toggle: hiding evidence by default lets a viewing preference quietly decide what the
  corpus appears to contain. Authored edges carry no confidence at all, and the field's contract is
  that absence means "authored, not scored" — never "confidence zero" — so the threshold must not
  touch them. The outranking detail is the subtle one: one line is drawn per PAIR and the most
  consequential relationship wins, so a hidden low-confidence edge that still competed could win its
  pair and blank the visible relationship underneath it.
- A: A continuous slider — rejected: invites thresholds that correspond to nothing the data records.
  Hide low-confidence edges by default — rejected, per the evidence-hiding argument above.
- F: `memory-trace/client/src/GraphWorkspace.tsx`, `memory-trace/client/src/App.tsx`,
  `memory-trace/client/src/SettingsMenu.tsx`, `memory-trace/client/src/styles.css`.
- T: Typecheck clean; verified live on the real corpus — 98 edges (51 scored, 47 authored); ≥0.7
  leaves 81 (hiding exactly the 17 below it), ≥0.9 leaves 60 (hiding the 38 below it), All restores
  98. The 47 authored edges survive every threshold.
