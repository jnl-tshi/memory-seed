#### D1 - Fail-open to `automatic`, opt this repo into `manual`

- D: `read_merge_trigger` fail-opens to `automatic`; this repo declares `merge_trigger: manual` in

- R: The proposal left the default open (§6.1) and it is the breaking-change lever. Fail-open `manual`

  update — a behaviour change for all downstream consumers. Fail-open `automatic` preserves legacy
  exactly, matching how `read_integration_mode` fail-opens to keep unconfigured projects unchanged, and
  it keeps every existing temp-repo test green (they default to automatic = no gate). Measured the blast
  radius first: 183 references across 47 files, all docs/tests/narrative, zero automated or CI callers —
  so nothing breaks silently in a pipeline either way, and the only real consequence is downstream
  human/agent CLI usage, which `automatic` leaves untouched.

#### D2 - Gate placement mirrors the asymmetric `pr` precedent, plus a deliberate strengthening

- D: MCP `memory_session_integrate` declines under `manual` (no flag — declining IS the gate). CLI
  `session merge-branch`/`open-pr`/`integrate` require `--user-approved` under `manual`.
- R: The existing `pr` gate is already asymmetric — the MCP declines `pr` ("not run unattended") while
  the CLI proceeds to `open_pr`. That is the design language: gate the autonomous surface, trust the
  attended one. The MCP is the agent's unattended path and cannot represent user authorization, so it
  declines and hands over the CLI command. The honest part, recorded so it is not mistaken for a mirror:
  the CLI flag goes BEYOND the pr precedent, which trusts the CLI entirely. It is the deliberate teeth
  JNL chose over a pure agent-contract, because the proposal's whole thesis is "don't rely on the agent
  remembering" and a contract is exactly that reliance. A CLI cannot tell an agent-initiated call from a
  user one, so "refuse to auto-run" needs a token representing user approval — the flag is that token,
  the same shape as `--allow-root-write`.

#### D3 - A dry run is never gated

- D: The gate is skipped when `dry_run` is set, in both the CLI handoff functions and the MCP path.
- R: A dry run previews the fuse plan and lands nothing, so gating it would only deny agents a safe,
  useful read. This diverges slightly from the pr decline (which returns regardless of dry_run), and the
  divergence is intentional: previewing under `manual` is exactly what an agent should do while waiting
  for the user's go.

#### D4 - `--user-approved`, not a generic `--yes`

- D: The flag reads as authorization; its help text and the block message name it as the user's

- R: A generic `--force`/`--yes` would teach nothing about what it means. The refusal message and the
