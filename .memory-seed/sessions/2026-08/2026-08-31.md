  against treating a prior session's non-action as blanket precedent for later turns. Investigation
  traced Run 7's compliance regression (5 decisions logged vs. Run 6's 10, on an identical fixture)
  to the new git-diff message's own wording, not the trigger mechanism: it fired exactly as
  designed (`consecutive_misses: 7`), but its impersonal, historical framing ("the working tree has

  enough guardrail before this regression to have built the whole system on it.

### Decisions

#### D1 - Turn-anchor the hook's reminder wording and close the "not my work" loophole

- D: Reworded all three `session-log-check.py` reminder messages. The git-diff first-fire message
  drops "the working tree has changes... detected from git" in favor of turn-anchored phrasing,
  regains the first-fire urgency ("before this turn ends - not deferred, not batched") that only
  the escalated message previously carried, and adds: "not skipped because the changes predate
  this turn: whichever turn is running when this fires is responsible for logging them." The same
  clause (adapted) was added to the stale-only and escalated/repeated messages so tone doesn't
  differ by which check fired. Drive-by fix: dropped "even if it is a small-work entry with no real
  decision. D and R are required" from the git-diff message - internally contradictory, since the
  small-work template has no D/R fields at all; replaced with a pointer to use that template when
  there's no real decision.
- R: Given an identical seeding brief in both runs, the pre-fix session never engaged with the
  leftover dirty tree at all; the post-fix session, seeing only the new hook's impersonal wording,
  wrote a rationalization with no antecedent except that wording. The old time-based message
  ("no entry has been logged... before this turn ends") could not support that reading; the new one
  could. Restoring turn-anchored, first-fire-urgent phrasing and explicitly foreclosing the
  "predates this turn" excuse addresses the mechanism directly rather than guessing at a broader fix.
- A: Considered leaving the trigger mechanism as-is and only adding the anti-rationalization clause
  to the escalated message (which already had strong wording) - rejected because the escalated
  message only fires on a SECOND miss, and the regression's root instance (S5) was a first-fire.
- F: `.memory-seed/hooks/session-log-check.py`, `memory_seed/seed/.memory-seed/hooks/session-log-check.py`,
  `tests/test_session_log_ordering_hook.py` (3 new assertions on existing tests covering each branch).
- T: `pytest tests/test_session_log_ordering_hook.py -q` - 20 passed. `diff` confirms both hook
  copies stay byte-identical.

  Rules gained: "Do not borrow a prior entry's stated non-action... as your own R:" - the shape S5

  `.memory-seed/agent-rules.md`'s End Of Turn section gained a broader rule: a prior session's
  choice not to log/act is scoped to exactly what it named, not blanket precedent - logging your
