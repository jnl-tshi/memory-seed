### Summary

- The append-only correction mechanism finally has a tool: `link retract` (CLI) and
  `memory_link_retract` (the first MCP link-write tool) render a correctly-grammared retract or
  retract-and-retype block, pre-validated against the same rules `links check` enforces after the
  fact. Implemented by an opus subagent against the approved plan; reviewed and landed here.
- The build surfaced a latent checker defect: `links check` counted an edge as "declared" only
  from link sidecars, so a retract of an entry-YAML edge - which the reader has honoured since
  2026-08-09 - would have been reported as dangling. Fixed, verified byte-identical on the live
  corpus (179 issues before and after; the defect was latent here, not firing).

### Decisions

#### D1 - Retract-and-retype is a command on both surfaces, refused before it can go wrong

- D: `apply_link_retract` renders ONE sidecar block - wall-clock heading, `retracts:` with one
  line per ordinal (comma multi-ordinal input fans out), optional re-authored edge of the new
  kind/type, `note:` passthrough - through the shared chronological writer stack, filed under the
  source entry's own session date. Pre-validation mirrors the checker: unknown kinds, malformed
  refs, undeclared edges (dangling), a taken refines slot on retype, a date pin that is not the
  declaration date, and a colliding `(entry_id, heading-stamp)` block identity are all refused
  BEFORE anything is written. CLI `link retract <kind> <ref> --from <entry>` follows `link add`'s
  write-then-recheck pattern; MCP `memory_link_retract` follows the session-append write-tool
  shape with dry_run, no merge_trigger gate (an append-only correction, not an integration).
- R: Retract-and-retype is the mandated fix for three `links check` errors, yet every retract in
  the corpus was hand-formatted markdown - the system's only sanctioned correction path had the
  highest authoring friction and no guard between the author and a malformed or dangling block.
  Pre-validation at the moment of writing is the same argument as every write-time gate here: the
  refusal costs a keystroke now instead of a checker error after publication.
- A: A `reclassifies:` one-liner (retract-plus-readd sugar in the grammar) - stays deferred per
  the spec doc; the command gives the same ergonomics without a second grammar surface.
- F: memory_seed/core.py, memory_seed/cli.py, memory_seed/mcp_server.py,
  tests/test_link_retract.py, tests/test_links_check.py, tests/test_mcp_session_append.py,
  docs/3_Spec/draft/link-retraction.md, CHANGELOG.md
- T: Twenty new tests across core/CLI/MCP - including retype-to-refines refused when the slot is
  held by another entry but allowed when held by the retracting entry itself, dry-run writes
  nothing, and the previously uncovered `retract-before-declaration` checker rule. The MCP
  write-surface pin widened explicitly from two tools to three. Full suite 1433 on the branch.

#### D2 - The checker's declared-edge index includes entry-YAML edges

- D: `check_session_links` feeds entry-YAML lifecycle edges into `declared_entry_edges` /
  `declared_decision_edges` / `declared_edge_dates`, so a retract naming an entry-YAML edge
  validates instead of reporting `dangling-retract`.
- R: The reader has honoured retracts of entry-YAML edges since 2026-08-09; the checker still
  believed only sidecars declare edges, so the reader and its integrity gate disagreed about
  which retracts are legal - the command's own primary use case was unreachable. Verified
  read-only on the live corpus before and after: 179 issues, byte-identical - latent, not firing.
- A: none considered viable; the asymmetry was simply an omission.
- F: memory_seed/core.py, tests/test_links_check.py
- T: `test_retract_of_an_entry_yaml_edge_is_not_dangling`; the declared-edge collector agrees
  with the checker by test rather than shared code - noted in-code for whoever changes the
  identity tuple next.
