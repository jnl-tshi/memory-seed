  approved plan and reviewed here. `esr --json` now carries both ADR queues, and the review-queue

### Decisions

#### D1 - Both ADR queues reach esr --json, and a completeness guard makes the next omission loud

- D: `EsrReport.to_dict()` gains `adr_attachment_candidates` and `adr_head_reviews` as top-level
  keys named after their fields; every existing key (including the `last_sidecar_date` rename and
  the nested `diagrams` bucket) stays byte-stable. A new field-by-field completeness test walks an
  explicit path table so any future EsrReport field missing from the dict fails a test instead of
  silently vanishing from automation.
- R: Both queues rendered only in prose - the sections shipped without their JSON surface, twice,
  because nothing checked coverage. The guard converts the class of bug into a test failure; the
  shape-stability constraint exists because downstream consumers replay stored payloads.
- A: Restructuring the JSON (renaming the diagrams bucket, nesting an adrs block) - rejected:
  shape stability outweighs tidiness on a consumed payload.
- F: memory_seed/esr.py, tests/test_esr.py, CHANGELOG.md
- T: Completeness walk over every dataclass field; both keys list-typed for a populated queue;
  first CLI-level `esr --json` smoke test. Full suite 1168.

#### D2 - The review-queue preamble states both answer paths, because one of them has no command

- D: The `## ADR review queue` preamble names the revision pair (`adr revise` then
  `adr transition --status accepted`, after authoring the successor decision entry) and states
  that reviewed-no-change is recorded ONLY through the MCP `memory_session_append` review gate
  (`{"outcome": "no-change", "reason": ...}`) - the CLI has no equivalent. Syntax lives once at
  section level (the diagram-section precedent); per-ADR line formats are byte-identical.
- R: A queue that tells the reader what is stale but not how to answer it routes every flag
  through re-discovery. The honest version of "carry the command" is naming the mechanism,
  because the no-change path has no command to carry - which is itself the finding.
- F: memory_seed/esr.py, tests/test_esr.py
- T: Rendered-section assertions for the revision pair and the no-change mention.

### Summary

- The graph assertion that has twice caught silent edge loss - `links check` read OK across both -
  is now a command instead of a throwaway campaign script: `links graph-diff` snapshots the
  effective evolves graph and gates a later comparison on the edge set being unchanged.
  Implemented by a sonnet subagent against the approved plan; reviewed and landed here.

### Decision

- D: `effective_graph_snapshot(cwd)` serialises the effective graph (schema_version 1,
  `corpus_revision` git-pin per the quality-report convention, aggregates, per-node sorted
  `evolves` targets, decision-keyed `refines_successors`); `diff_graph_snapshots` names every
  per-node delta. CLI `links graph-diff --snapshot <path>` / `--against <path> [--json]`. The GATE
  is the entry-level evolves edge set only - any per-node addition/removal or evolves-aggregate
  delta fails (exit 1); refines/typing deltas are reported but informational, so a pure retype
  campaign passes. Exit 2 for unusable baselines (missing, malformed, schema mismatch).
  `link_swarm.md` (+ byte-identical seed twin) now instructs every bulk sidecar write to bracket
  with snapshot/against, and states plainly that `links check` alone is not sufficient.
- R: The assertion earned tool status the hard way - 807 edges vanished under a green `links
  check`, then a +3 resurrection was caught only by the same hand-rolled check in a second
  throwaway script. A gate that must be copy-pasted per campaign is one omission from not
  existing. The typed-delta exemption matches the assertion's history exactly: both real uses
  gated retype campaigns whose refines counts changed BY DESIGN while the edge set had to hold.
- A: Auto-persisting baselines to a fixed location - rejected: explicit paths, nothing committed,
  no hidden state; the caller owns the snapshot's lifetime.
- F: memory_seed/retrieval.py, memory_seed/cli.py, tests/test_graph_diff.py,
  .memory-seed/skills/link_swarm.md, memory_seed/seed/.memory-seed/skills/link_swarm.md,
  CHANGELOG.md
- T: Eleven new tests - snapshot shape, empty corpus, unchanged/added/removed edges, the
  retype-is-informational case, three unusable-baseline exits, CLI usage errors. Seed twins
  byte-identical (filecmp). Full suite 1175 on the branch.
