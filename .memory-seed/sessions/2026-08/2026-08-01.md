### Summary

- Restored decision-selector navigation when ontology filters retain an Inspector entry outside the workspace result, and removed the repeated vocabulary reads that made topic clicks take several seconds.

### Decisions

#### D1 - Resolve Inspector decisions from the full entry index

- D: Resolve a selector click's decision row from the full Trail entry index, while leaving the active ontology response responsible only for workspace membership.
- R: The Inspector deliberately preserves a selected entry as context when it falls outside the current filter. Searching only that filtered payload therefore made every sibling selector button a silent no-op even though the complete authored entry remained visible.
- A: Clearing the Inspector selection when filtering was rejected because it would discard useful context and contradict the coordinated-facet decision. No diagram was added because this is a local state-source correction without new durable topology.
- F: `memory-trace/client/src/App.tsx`, `memory-trace/client/src/trailModel.ts`, `memory-trace/client/src/trailModel.test.ts`, and generated production assets under `memory-trace/memory_trace/static/react/`.
- T: Live Trail and Graph checks with an entry outside the active Area filter moved D2/D3 selection and the nested decision scroll while the outer Inspector remained at scroll position 0; 231 frontend tests passed.

#### D2 - Share one parsed topic vocabulary per Trace request

- D: Load `topics.yaml` once per Graph or Trail request and pass that immutable `TopicIndex` through ontology matching, contextual counts, hierarchy rendering, and decision-row attribution.
- R: The previous helper boundary reparsed the same file once per entry for filtering and twice per entry for self-excluding counts—more than 2,000 reads on the current corpus and about four seconds for a warm filtered Trail response.
- A: A persistent cross-request memo was rejected because the vocabulary intentionally remains fresh outside the projection cache generation; request-scoped reuse removes the repeated work without serving editorial changes stale. The first worktree typecheck could not resolve frontend dependencies, so validation used a temporary junction to the primary checkout's installed dependencies and removed it afterward.
- F: `memory_seed/topics.py`, `memory-trace/memory_trace/service.py`, and `memory-trace/tests/test_ontology_facets.py`.
- T: Warm filtered Trail requests measured about 60-90 ms and filtered Graph projection requests about 19-25 ms after the change, versus roughly 3.8-4.0 seconds and 375-397 ms before it. Targeted Python suites, TypeScript typecheck, production build, and `git diff --check` passed.

### Implementation

- Added a pure decision-row resolver so the selection source is explicit and testable.
- Removed the process-global axis cache, which was rooted at `.` and could be wrong for another worktree, in favour of the request's correctly scoped vocabulary index.

### Validation

- Python ontology, Trail-row, service, v1 contract, OpenAPI fixture, and topic suites passed.
- `npm test` passed 231 tests; `npm run typecheck` and `npm run build` passed.
- Live browser verification covered filtered Trail and Graph selector navigation plus warm filter timing.

### Follow-up

- None. The first request against a brand-new Trace cache still pays the normal cache-build cost; subsequent ontology interactions use the optimized path.
