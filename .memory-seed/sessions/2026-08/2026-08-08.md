### Summary

- JNL hit "Failed to parse frontmatter" in the Trace UI. Five ADR titles contain `": "`, which YAML
  reads as a nested mapping; `render_adr` wrote titles unquoted. Four of the five predate today.
- Fixed at the writer (quote only when needed, so the corpus written before stays byte-identical),
  repaired the five, and added a frontmatter linter to `adr check` and the fuse.

### Decisions

#### D1 - Quote a frontmatter scalar when YAML needs it, and only then

- D: `render_adr` renders the title through `_yaml_scalar()`, which quotes a value that contains
  `": "` or `" #"`, ends in a colon, opens with a YAML indicator, or carries edge whitespace. The
  five affected files were repaired by re-rendering, with the repair refusing to write if the diff
  touched anything but the title line.
- R: Our own reader is a regex (`_scalar`) and accepts frontmatter no YAML parser would, so five
  broken titles sat in the corpus unnoticed - `adr check` was green throughout. The Trace UI parses
  properly and failed. Quoting conditionally rather than always is what keeps every record written
  before this byte-identical, which matters because three ADRs are sha256-pinned by the codex
  fixtures. Re-rendering IS the repair: the contract already calls metadata repair an explicit
  file-repair operation rather than a lifecycle event, so no ledger events were added.
- A: Quote every scalar unconditionally. Rejected - it rewrites 40 files including the three pinned
  ones, turning a five-file repair into frozen-source drift.
- A: Rename the titles to avoid colons. Rejected - the corpus should carry the title the concern
  deserves; the writer is what was wrong.
- F: `memory_seed/adr.py`, five files under `.memory-seed/decisions/`
- T: All 40 ADRs now parse under a real YAML parser (0 failures, was 5); pinned three
  byte-unchanged; titles read back with their colons intact.

#### D2 - Lint the raw frontmatter, because the canonical check names the wrong half

- D: `frontmatter_issues()` lints raw frontmatter for unquoted risky scalars, tabs, duplicate keys
  and missing fences, naming the cause ("must be quoted: it contains ': ', which YAML reads as a
  nested mapping"). Wired into `check_adrs` and into the fuse's ADR path, which refuses before
  parsing.
- R: Once the writer quoted correctly, the existing byte-canonical comparison did catch all five -
  but only as "derived Current view is stale", which points at the ledger when the fault is in the
  header. A check that detects without diagnosing costs the next reader the same hour it cost me.
  The linter is hand-rolled because `model2vec` is the package's only dependency, so no YAML
  library is available to validate with; hand-rolling the risk cases is the price of that
  constraint and is why the rule list is explicit rather than delegated.
- A: Add PyYAML as a dependency to validate properly. Rejected - one required dependency is a
  standing decision, and this check needs five string tests.
- F: `memory_seed/adr.py`, `memory_seed/core.py`, `tests/test_adr_contract_extension.py`
- T: Four new tests - a risky title quotes and round-trips, a safe title stays bare (the
  byte-stability guarantee), the linter names each cause, and every live ADR passes. Full suite
  1118.

### Facts

- Detection existed and diagnosis did not: `adr check` would have flagged these the moment the
  writer was fixed, but as a stale-view error. The linter exists for the message, not the catch.
- The same leniency may affect other sidecar families - link sidecars carry a free-text `note:`
  that could contain `": "`. Not investigated here; worth a sweep.
