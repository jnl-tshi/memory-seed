### Summary

- Wired the agent-capture experiment's Codex arm and validated the instrument end to end with two
  unscored probes: an L0 MCP write that landed in the fixture store with the parent untouched, and an
  L3 run whose own SessionStart hook and git commit hook both fired inside the fixture.

### Decisions

#### D1 - Adopt four Codex harness constants, each forced by an observed failure

- D: The Codex runner passes `-c projects={"<run dir>"={trust_level="trusted"}}`,
  `--dangerously-bypass-approvals-and-sandbox`, `-c features.apps=false`, and pins the MCP server's
  `cwd` to the run directory per run rather than in the template.
- R: None is cosmetic. Codex loads project-scoped `.codex/config.toml` and `.codex/hooks.json` only
  for trusted paths and every run directory is a fresh untrusted path, so without the trust
  override L0 has no write path and L2/L3 have no hooks. `approval_policy="never"` does not cover
  MCP tool calls - a probe with it set returned `user cancelled MCP tool call` - so the approvals
  bypass is the only headless route, the direct analogue of Claude's `--dangerously-skip-permissions`.
  This machine's Codex exposes 240 MCP tools costing ~139k input tokens of tool surface per turn;
  `features.apps=false` removes them while leaving the memory-seed server intact. And the stock MCP
  entry leaves `cwd` unset, which matters because the server resolves `cwd="."` against its own
  process cwd (H4) while `resolve_runtime` walks upward with no boundary guard (H1) - unpinned, a
  write could silently land in the PARENT store while the agent reported success.
- A: The whole-table `projects={...}` form was chosen over the dotted
  `projects.<path>.trust_level` path because the dotted-path parser splits on `.` and would break on
  any path containing one. `--ignore-user-config` was tested as a way to get a clean environment
  independent of the user's config drift and rejected: it drops the project layer too, so the
  memory-seed server disappeared. `--disable apps` (the flag form) was rejected in favour of
  `-c features.apps=false` after the model's self-reported tool list proved unreliable in both
  directions - the question was only settled by making an actual `memory_topics_list` call.
  `--dangerously-bypass-hook-trust` was NOT adopted: the probe showed injected trust already covers
  hook trust, so carrying it would have been an assumed rather than a demonstrated constant.
- F: `experiments/agent-capture/run.py`, `experiments/agent-capture/generate_fixtures.py`.
- T: Fixture determinism re-verified for all four Codex levels (byte-identical tree hashes across a
  regeneration); parent `links check` (153 files) and `docs check` (191 files) both OK.

#### D2 - Codex validates the instrument, not the hypothesis, and its results are never pooled

- D: Record the Codex arm in PREREGISTRATION.md as a dated append with an explicit no-pooling rule,
  add a `--brief` probe override that `collect.py` excludes from every scored table, and fingerprint
  the parent repo before and after each run into `parent_isolated`.
- R: JNL authorised Codex only because the Claude CLI's OAuth had expired, so these runs answer
  "does the harness work", not "do agents capture decisions". Two independent facts make the arms
  non-comparable: a different tool surface and system prompt, and a materially thinner transcript -
  Codex `--json` emits `mcp_tool_call` items and the final message but no reasoning items, only a
  token count, so faithfulness can only be judged there against observable behaviour. Amending by
  append rather than edit is the same append-only discipline the product sells. The parent
  fingerprint is asserted per run rather than assumed because the approvals bypass also drops the
  sandbox.
- A: Editing the pre-registration in place was declined as a silent rewrite of a document whose
  whole value is being fixed before the result. Deferring the Codex arm until Claude auth returned
  was declined because the instrument's hazards are agent-independent and finding them now is free.
- F: `experiments/agent-capture/PREREGISTRATION.md`, `experiments/agent-capture/README.md`,
  `experiments/agent-capture/collect.py`.
- T: Probe A wrote one entry to `<run>/.memory-seed/sessions/2026-08/2026-08-04.md` with the parent
  store unchanged at 154 files / 2,729,148 bytes, and the store's validators refused the first
  malformed append; probe B stamped `Memory-Entry: mse_dm8fjga4gn7znzg8` on fixture commit `94b7cd9`
  with the fixture's SessionStart orientation block visible in its stderr, while L0 produced neither;
