### Summary

- Fixed `memory-seed quality report` mis-measuring when invoked from a subdirectory of the runtime root: the join base for session files came from the raw cwd rather than the runtime workspace root, so no session file was ever read and `draft_reason_coverage` reported a number it had not measured.

### Decision

- D: Derive the session-file join base in `build_quality_report` from `resolve_runtime(cwd).workspace_root` instead of `Path(cwd)`, and delete the `except OSError: continue` that was hiding the missed reads.
- R: `chunk.source_path` is relativized against `runtime.workspace_root` by the extractor, so joining it onto a cwd one directory down misses every file; the swallow then turned that into an empty `format_issues`, which the coverage metric reads as zero failures and renders as 100%. Reusing `resolve_runtime(...).workspace_root` matches the idiom already established for Evidence Pack validation rather than inventing a second convention. The swallow had to go with it: once the base is right, a missed read is a broken invariant, and a report whose whole purpose is honest measurement must fail rather than emit a figure it did not compute.
- A: Keeping the `except OSError` as a defensive guard was rejected - it is precisely the mechanism that converted a path bug into a plausible-looking number, and the module's own docstring makes "never render nothing-measured as 100%" a load-bearing rule. Degrading the single metric to `unavailable` instead of raising was considered and left alone: it is a wider design call about per-metric failure than this defect warrants.
- F: `memory_seed/quality.py`, `tests/test_quality.py`
- T: `python -m pytest tests/test_quality.py` - 10 passed. The new `test_subdirectory_cwd_measures_the_same_corpus_as_the_runtime_root` was confirmed to fail against the unpatched module (reported 2/2 from the subdirectory where the true figure is 1/2), so it is a real discriminator rather than a test that passes either way. Full suite: 845 passed, 7 pre-existing seed-twin parity failures unrelated to this change and reproduced on a clean tree at the same commit. CLI verified by hand from `memory-trace/`: 50/50 session files now resolve, against 0/50 before.
