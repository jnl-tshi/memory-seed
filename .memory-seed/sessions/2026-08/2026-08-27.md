### Summary

- Documented the accepted provisional model-tier task-packet budgets, the evidence boundary behind them, and their consequences for ESR/ADR orchestration.
- Kept the assessment in the reference lane because it records research and an operating baseline; implementation in the sweep skills remains a separate change.

### Decisions

#### D1 - Adopt capability-tier task-packet bands

- D: Use 16K/24K/32K target-soft-shard thresholds for economy workers, 32K/48K/64K for balanced workers, and 64K/96K/128K for frontier workers.
- R: Advertised context capacity is not a reliable inference limit. Larger models can accept more prepared evidence, but all tiers should still receive the smallest sufficient packet rather than a corpus dump.
- A: A universal 32K ceiling was rejected because it confuses the economy-tier safety boundary with larger-model capacity. Scaling linearly to each model's full context window was rejected because retrieval distraction, synthesis quality, latency, and cost do not scale with the advertised request limit.
- F: `docs/4_Reference/model-tier-task-packet-budget-assessment.md`, `docs/4_Reference/README.md`, and `docs/README.md`.
- T: `python -m memory_seed.cli docs index --check`, `python -m memory_seed.cli docs check`, and `git diff --check` passed; docs check retained 16 pre-existing incomplete-metadata warnings.

#### D2 - Route sweeps by packet tokens and worker tier

- D: Make estimated prepared-packet tokens and the selected leaf worker tier the primary ESR/ADR orchestration signal; retain the existing 20-candidate threshold only as a compatibility fallback when token estimation is unavailable. Use a lightweight offline estimate with safety margin, then provider-native counting at dispatch when available.
- R: Candidate count ignores variation in evidence size and decision-chain density. The worker receiving a leaf packet determines its safe band; a frontier orchestrator does not raise an economy worker's shard limit. A built-in approximation preserves the network-free core, while provider counts provide model-specific request-fit and benchmark evidence.
- A: Adding a mandatory tokenizer or network dependency to the core was rejected because tokenization differs across providers and the core must remain network-free and model-independent.
- F: The accepted design and benchmark requirements are recorded in `docs/4_Reference/model-tier-task-packet-budget-assessment.md`; `.memory-seed/skills/adr_sweep.md` and `.memory-seed/skills/end_of_turn.md` are deliberately unchanged pending implementation.
- T: The assessment identifies generic benchmark evidence separately from the provisional engineering defaults and specifies the Memory Seed benchmark required before durable locking.

### Follow-up

- Implement the estimator and replace the sweep's candidate-count-first routing in a separate, tested workstream.
- Run provider-counted packet benchmarks before promoting the provisional thresholds into durable skill behavior.
