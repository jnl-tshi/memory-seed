### Decisions

#### D1 - ESR owns inverse ADR coverage with attached recommendations

- D: ESR now derives same-area connected components over decision-level `evolves` and `replaces`
  lineage. It reports unclaimed chains, weaker unclaimed pairs, and claimed chains with unnamed
  growth. Every item carries a deterministic advisory recommendation and is present in both text and
  JSON output; discovery never creates an ADR, attaches a member, or moves a head.
- R: The mechanism was deliberately left experimental until repeated cycles demonstrated useful
  candidates. That evidence now exists, and keeping the check in a one-off campaign script lets ADR
  coverage decay invisibly. Structured recommendations satisfy the human review contract without
  turning mechanical discovery into authority.
- A: Copy the experiment into the runbook. Rejected because ESR already owns standing mechanical
  checks and the production corpus readers; a second parser would recreate the normalization drift
  the experiment itself was written to prevent.
- F: `memory_seed/esr.py`, `tests/test_esr.py`, `.memory-seed/index.md`.

#### D2 - ADR sweeps default to one orchestrator and fan out read-only at 20

- D: The new core `adr_sweep.md` skill uses Level 1 single-orchestrator, human-gated review for fewer
  than 20 unresolved candidates. At 20 or more, or for cleanly separable domains, Level 2 bounded
  read-only fan-out is available with user approval; one orchestrator reconciles results and owns the
  final recommendation batch. Workers never write memory or ADR state.
- R: Small queues benefit from cross-candidate consistency and are faster to read directly. The live
  queue is now 96, so the historical threshold has been reached and a bounded fan-out would earn its
  coordination cost when the user runs the adjudication sweep. Fan-out changes review capacity, not
  authority.
- A: Always run a swarm. Rejected because ordinary small queues cost less to review in one context.
  Always stay single-agent was also rejected because the measured live queue now exceeds the recorded
  threshold by nearly five times.
- F: `.memory-seed/skills/adr_sweep.md`, its seed twin and registries,
  `.memory-seed/skills/end_of_turn.md`, `memory_seed/core.py`, `pyproject.toml`, and registry/lifecycle
  tests.
- T: Focused ESR, schema, and project-lifecycle suite: 92 passed. Real ESR JSON: 96 candidates and

- A: No decision diagram sidecar was added: the two-level threshold and linear
  discover-recommend-approve-write flow are already explicit in the skill, so a diagram would repeat
  the prose without exposing another dependency or branch.
