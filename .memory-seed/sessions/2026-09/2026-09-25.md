### Summary

- Replaced worktree-per-session churn with one persistent home worktree per agent, following a 2026-09-25 Design Discovery with JNL.

### Records

#### D1 - Decision: One persistent home worktree per agent, task branches inside it, overflow for concurrent sessions
- D: Each writing agent owns `<namespace>/home` (`<namespace>/<user>/home` with 2+ participants). `memory-seed worktree home --claim --branch <agent>/<kind>/<topic>` (MCP `memory_worktree_home`) creates the home if needed, takes a lease stored in the worktree's git admin directory, and checks out a task branch from `main`. A fresh lease held by another session yields an `overflow-<id>` worktree with the old remove-after-merge lifecycle. `session merge-branch` parks a merged home (detached at the merge commit, lease released, status `parked`) instead of removing it. `--park` handles merges made elsewhere. Leftover uncommitted work stops a claim with exit 3 and goes to the user; an inactive clean unmerged branch needs `--resume`.
  - Scope: `memory_seed/worktree_home.py`, merge cleanup, worktree GC, guard, CLI/MCP, the session-start and file-touch hooks, and the `agent_collaboration.md` and `worktree_reconciliation.md` skills (live and seed).
  - Disposition: Implemented on JNL's approval of the Design Discovery plan.
- R: A fresh worktree per session broke venvs, stranded folders, and on 2026-09-24 let a session gut its own launch worktree, which blocked every later commit. The accepted convention was already "worktree = session environment, branch = task". The churn came from app defaults and a Finish Contract that removed the worktree after each merge. Using detached HEAD as the free state needs no lock file, and existing GC already leaves detached worktrees alone.
- A: Keeping per-session worktrees and fixing only cleanup was rejected: it removes neither the churn nor the launch-folder lock. Sharing one worktree between concurrent sessions was rejected: they share a single checked-out branch and uncommitted files. Auto-committing leftover work to a rescue branch was rejected because it would commit unreviewed work.
- F: `memory_seed/worktree_home.py`, `memory_seed/core.py`, `memory_seed/worktree_gc.py`, `memory_seed/cli.py`, `memory_seed/mcp_server.py`, `memory_seed/esr.py`, `.memory-seed/hooks/session-start-context.py`, `.memory-seed/hooks/file-touch-decisions.py`, `.memory-seed/skills/agent_collaboration.md`, `.memory-seed/skills/worktree_reconciliation.md`, their seed twins, `CHANGELOG.md`, `tests/test_worktree_home.py`, `tests/test_session_fuse_and_merge.py`, `tests/test_worktree_gc.py`, `tests/test_esr.py`, `tests/test_mcp_server.py`.
- T: 19 new home-lifecycle tests (claim, overflow, stale resume, stale dirty, park, release, heartbeat, guard, CLI, MCP, local-ignore), 3 merge-cleanup tests (home parked, dirty home retained, overflow still removed), and a GC home-never-removable test all pass.
