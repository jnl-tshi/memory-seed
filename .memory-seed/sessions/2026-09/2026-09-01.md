### Summary

- Diagnosed the specific, evidence-based mechanism behind S4/S6's persistent non-logging (open
  since Run 9): a targeted replay with full transcripts (not the 300-char summaries `dryrun.py`
  keeps) showed both sessions break the orientation chain (SessionStart hook pointer -> AGENTS.md
  -> agent-rules.md, where the actual "you must log" rule lives) rather than reasoning their way
  past it. S4 never opens `AGENTS.md` at all (no `Read`, no `cat` - two tool calls total: a
  file-existence check, then `Write`). S6 *does* read `AGENTS.md` in full (73 lines, nothing
  truncated) but never follows its own explicit "1. Read `.memory-seed/agent-rules.md`" instruction
  - stops at the entry point and goes straight to the task files. Both share one root cause: every
  step in the chain reads as a numbered checklist, and nothing states the chain must *complete*,
  not just be opened, before the task starts. Made both links of the chain state that explicitly.

### Decisions

#### D1 - State the orientation chain as a mandatory gate, not a numbered checklist

- D: `.memory-seed/hooks/session-start-context.py`'s injected `STARTUP ORIENTATION` block (live +
  seed twin) now leads with "mandatory, complete before any task action, however small the task
  looks" and states explicitly that reading `AGENTS.md` is the routing step, not the destination.
  `AGENTS.md`'s own "Operating Mode" section (root file, identical to `memory_seed/seed/AGENTS.md`
  - kept in sync) gained a parallel sentence: these steps must all complete before acting on the
  task, and reading this file does not itself satisfy step 1's instruction to continue into
  `agent-rules.md`.
- R: The diagnostic evidence names two distinct failure shapes at two different points in the same
  chain - a full skip (S4) and a stop-at-entry-point (S6) - and both share the same underlying gap:
  nothing in the existing wording asserts these steps are prerequisites rather than best-practice
  guidance a model judging its own task as simple can silently truncate. Fixing both links with the
  same gating language addresses the shared root cause rather than patching each session's specific
  behavior.
- A: Considered duplicating the logging mandate itself earlier in the chain (directly into
  `AGENTS.md` or the SessionStart injection) - rejected: `AGENTS.md` is deliberately a thin,
  tool-agnostic router by design (per `ms-5e366ef4`'s "SessionStart hook injects content, not a
  'go read it' nudge" precedent and the file's own stated purpose), and duplicating rules that live
  in `agent-rules.md` would blur that separation for a problem that is actually about completing
  the routing, not about where the rule itself lives.
- F: `.memory-seed/hooks/session-start-context.py`, `memory_seed/seed/.memory-seed/hooks/session-start-context.py`,
  `AGENTS.md`, `memory_seed/seed/AGENTS.md`.
- T: `pytest tests/test_session_start_hook.py tests/test_session_schema.py` - 47 passed, 4 subtests
  passed. `pytest tests/test_project_lifecycle.py tests/test_hook_merge.py tests/test_mcp_merge.py
  tests/test_agent_selection.py tests/test_cli_help.py` - 118 passed, 3 subtests passed (broader
  suite touching `AGENTS.md` content/merge behavior). `diff` confirms both file pairs stay
  byte-identical.

  stale copy of both files (`memory-system-version: 2.19` vs. this repo's current `2.20`, and the
