- D: `compile_task_packet`'s 20-iteration loop converges the packet's own serialized byte-length estimate

  2-cycle with no fixed point. Added cycle detection that keeps the safest (largest `total_input_tokens`)
  ledger from the cycle, and - after a first push exposed a second, independent self-consistency check
  further down that no cycle member could satisfy by construction - track whether the fallback ran and, only
  then, heal `serialized_packet_input_tokens` to the packet's real final measured byte count rather than
  raising on drift that has no fixed point to find. The normal single-fixed-point path is untouched and
  still hard-fails on any unexplained drift.
- R: `estimate_tokens` is a plain ceiling-division byte-length heuristic with no external dependency, so the
  same deterministic code producing different results on two machines meant the *input* differed, not the
  logic - most likely the embedded absolute checkout path's length shifting which byte-length boundary the
  self-reference lands on.
- A: Considered relaxing the final consistency check's exactness broadly; rejected because that would also
  hide genuine future regressions on the normal, convergent path. Healing only in the detected-fallback
  branch preserves the check's value everywhere else.
