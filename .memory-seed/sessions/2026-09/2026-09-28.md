### Summary

- Record the approved design for evidence-backed session checkpoints before implementation begins.

### Records

#### D1 - Decision: Replace stale-or-dirty reminder obligations with evidence-backed checkpoint debt

- D: The session-log hook will create immediate pending checkpoint debt only from locally observable Git evidence: changed tracked or untracked working-tree state, or a changed HEAD since the last valid session-entry baseline. A valid new session entry clears the checkpoint and re-baselines the evidence. Time alone never creates debt: after 15 minutes of clean read-only work, the hook emits one non-escalating agent-visible self-check per latest session entry, then stays silent.
  - Scope: The canonical session-checkpoint evaluator, operational state, and cross-agent hook delivery semantics.
  - Disposition: Approved for a staged candidate trial; it becomes the default only if the scenario gate passes.
- R: The existing `is_stale OR dirty_since_baseline` rule makes elapsed time manufacture obligations, while the user wants time to escalate genuine unresolved record obligations only. Git evidence remains the reliable cross-agent implementation signal, and the one-time clean advisory preserves a checkpoint for meaningful conversational decisions without creating debt.
- A: Keeping the OR-combined stale/diff trigger was rejected because clean read-only work repeats and escalates despite producing no record obligation. Removing time entirely was rejected because a clean conversation can still contain a meaningful decision that deserves an agent self-check.
- S: Governing accepted trigger ADR `.memory-seed/decisions/adr_session_log_trigger_enforcement.md`

#### D2 - Decision: Make classification closed and require deterministic proof for mechanical clearance

- D: The implementing agent classifies pending work with a closed rubric: small work produces a Summary/Validation record; new decisions produce Decision/Reason; changed decisions produce lineage-aware records; consequential ambiguity asks the user; and only proven mechanical work may clear without durable memory. Mechanical proof v1 supports whitespace-only tracked modifications from a clean baseline and refuses untracked, added, deleted, renamed, binary, semantic, dirty-baseline, and stale-checkpoint cases.
  - Scope: Agent-visible checkpoint resolution, the implementation checkpoint for small work, and the mechanical-proof boundary.
  - Disposition: Approved.
- R: Writing a fact into a project file is not itself memory, so S4/S6-style implementation work must yield at least a small-work obligation even without formal Design Discovery. A deterministic whitelist keeps mechanical clearance inspectable and prevents the hook from guessing away record debt.
- A: An external classifier service was rejected because classification authority stays with the implementing agent plus deterministic guards. Broad heuristic mechanical clearance was rejected because an old baseline stores only a hash and cannot prove a dirty historical preimage.
- S: Prior file-vs-memory decision `.memory-seed/sessions/2026-08/2026-08-31.md`

#### D3 - Decision: Use one canonical evaluator with versioned ignored state and parity across surfaces

- D: One runtime evaluator owns inspect and resolve behavior. The CLI exposes `memory-seed session checkpoint [--json]` and `memory-seed session checkpoint resolve --checkpoint-id <id> --proof whitespace-only [--json]`; MCP exposes `memory_session_checkpoint` with inspect/resolve modes. Ignored operational state is versioned, atomic, backward-compatible, and fail-open, carrying baseline HEAD, pending checkpoint evidence, first-seen time, one-time clean-advisory delivery, and last mechanical resolution. Live runtime and seed/template surfaces ship together with no opt-in flag.
  - Scope: CLI/MCP/hook architecture, state schema, write-surface parity, and rollout.
  - Disposition: Approved, conditional on the paired old-vs-candidate experiment and full policy-required verification.
- R: A single evaluator prevents CLI, MCP, and hook logic from drifting. Ignored state preserves Markdown as the only durable memory authority, and the trial gate proves the candidate reduces read-only false positives without lowering implementation capture before replacing the accepted default.
- A: Separate wrapper implementations and a second authoritative store were rejected because they violate single-source truth and local Markdown authority. An opt-in feature flag was rejected in favor of a staged experiment followed by one default.
- S: Append-only expression invariant `.memory-seed/decisions/adr_append_rule_is_an_invariant.md`
