### Summary

Interactive design discovery with JNL settled open decisions 7-12 of the hosted MVP programme. The programme, Next Steps and tournament plan now record the choices.

### Records

#### D1 - Decision: Human-confirmed approval with a signed-page fallback
- D: Approvals use the client's own confirmation surface (MCP elicitation or a Codex App Server approval event) that the agent cannot answer. Only when that is unavailable do they fall back to a minimal signed page for one mutation, which needs a fresh GitHub sign-in. That page is the only exception to "no launch UI dependency".
  - Scope: P0.2 approval delivery contract; P0.2 must verify which path Codex supports.
  - Disposition: Recorded in the programme's Approval delivery section.
- R: The working agent holds the member's credential, so service identity alone cannot prove a human approved.
- A: Out-of-band page only (always leaves the agent), scoped agent approval (approval stops proving a human decided), and push/OTP step-up (adds a second-device dependency).

#### D2 - Decision: Only adapter-attested user input counts as user direction
- D: Autonomous ordinary replacement requires events the client emits as user input, attested by the adapter. Agent text, tool results and quoted content never count. If Codex cannot separate these, every replacement stays pending. The capture contract gains a message-authorship field.
  - Scope: P0.2 capture field and P1.6 governance policy.
  - Disposition: Recorded in the programme's capture and governance sections.
- R: This reconciles the governance autonomy clause with the edition contract's rule that transcript role labels confer no authority.
- A: No autonomous replacement in the MVP (kept as the fallback), and attested input plus a confirm step (an approval per replacement).

#### D3 - Decision: PostgreSQL, shared schema with row-level security, local then managed, GitHub OAuth
- D: PostgreSQL is the MVP default, used with its own features; SQL Server is a later port. Tenancy is one shared schema with `tenant_id` enforced by row-level security. A local PostgreSQL server serves P0.2-P0.4 with simulated members, and managed PostgreSQL serves the P1.8 pilot. Identity is GitHub OAuth with device-code binding for the adapter.
  - Scope: P0.3 substrate prerequisites.
  - Disposition: Recorded in the programme's Engine, tenancy, hosting and identity section.
- R: JNL wants both engines eventually, but Postgres for the MVP, and prefers local infrastructure until real teammates join. Row-level security is directly testable by the release gate's negative controls.
- A: A portable engine layer or dual-engine CI from P0.3 (both rejected for MVP speed), and schema- or database-per-tenant (heavier operations). The managed IdP, cloud identity and Keycloak were not chosen.

#### D4 - Decision: Raw is visible only to its owner; curated records are shared; removal is a last resort
- D: A member's raw evidence is visible only to that member, with no lead or operator access; the curator is the only machine reader. Curated records are shared with the project by default, and the member whose evidence produced one is notified. Decisions change through `evolves` and `replaces`, and a reversal is a `replaces`. Removing a record is a last resort for a leaked secret or personal data, misattribution, or a curator fabrication. An author may remove their own record with a reason; removing another member's record needs lead-granted permission. Each removal leaves a tombstone without title or content. Raw fallback in retrieval is owner-only.
  - Scope: P0.4 curated-prose visibility and hosted privacy policy; content purge from backups stays in P1.7.
  - Disposition: Recorded in the programme's Privacy, retention and sharing and governance sections.
- R: JNL requires raw conversations never to be available to anyone else, and wants append-only history preserved. Lifecycle edges cannot fix content that should never have been shared, so removal remains as a narrowly gated exception.
- A: Lead permission for every removal (JNL's first proposal) was rejected on the agent's advice that authors must be able to retract their own sensitive content quickly. Author review before sharing, sharing without withdrawal, and per-project policy modes were rejected.

#### D5 - Decision: Evaluate the prose writer as a tournament track
- D: Add a Prose Writer Track to the tournament plan. It scores faithfulness, citation accuracy, abstention, privacy, cost and latency against a deterministic template-writer baseline, reported separately from classifiers.
  - Scope: P1.5 evaluation.
  - Disposition: Recorded in `decision-layer-model-tournament-plan.md`.
- R: One evaluation home with shared sealed fixtures, instead of a second harness.
- A: A separate writer plan (duplicate harness), and deferring with a template writer (defers the question).
- F: `docs/2_Todo/hosted-memory-mvp-programme.md`; `docs/2_Todo/0_NEXT_STEPS.md`; `docs/2_Todo/decision-layer-model-tournament-plan.md`.
