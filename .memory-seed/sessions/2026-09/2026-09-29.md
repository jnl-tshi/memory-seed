### Summary

- The Codex insights review found Codex respawning a stale 2.21.0 MCP server on 2026-09-23, because agent configs launch an unpinned `uvx --from memory-seed`. JNL asked for the launch to be pinned.

### Records

#### D1 - Decision: Pin the registered MCP server to the package version
- D: `core.PACKAGE_VERSION` (currently `2.23.0`) is a new version surface. `_MCP_SERVER_ARGS`, which every `_merge_*_mcp` upsert and the Codex TOML block write, is now `--from memory-seed==<PACKAGE_VERSION>`.
  - `update` rewrites existing unpinned or older `uvx`/`memory-seed-mcp` entries, because those commands are owned.
  - Deliberate local-build entries (`uv run ...`) are still preserved, per `test_mcp_local_build`.
  - `doctor` flags an unpinned or older entry as stale.
  - This repo's tracked `.codex/config.toml` is pinned to `2.23.0`, which is published on PyPI.
  - `release_publishing.md` (live and seed) lists `PACKAGE_VERSION` in the version-bump step. README and CHANGELOG are updated.
  - Scope: MCP registration written by `init`/`update`, and this repo's Codex config.
  - Disposition: implemented
- R: An unpinned `uvx --from memory-seed` lets uvx keep serving an old cached build. On 2026-09-23 Codex respawned a 2.21.0 server minutes after it was stopped, so Codex and Claude ran different versions. A pin makes the launched version explicit, and `update` moves it.
- A:
  - `memory-seed@latest` was rejected: a network check on every server start.
  - Reading the pin from installed package metadata was rejected: this machine's installed metadata says 2.20.0 while the checkout is 2.23.0, so a dev run would write a wrong pin. A constant guarded against `pyproject.toml` is exact.
- F: memory_seed/core.py, tests/test_mcp_merge.py, tests/test_processes.py, .codex/config.toml, .memory-seed/skills/release_publishing.md, memory_seed/seed/.memory-seed/skills/release_publishing.md, README.md, CHANGELOG.md
- T:
  - New tests:
    - `PACKAGE_VERSION` equals the `pyproject.toml` version;
    - `init` writes the pinned args (6 existing assertions now use it);
    - `find_managed_processes` still matches a `memory-seed==X` launch.
  - Full suite (`-n auto`): 2124 passed, 5 failed.
    - Four of the five pass serially (context-derivation, handoff-wiring, subagent-orientation).
    - `test_link_audit` fails on a HuggingFace "Fetching 10 files" progress bar in stderr, an environment embedding-cache effect unrelated to this change.
